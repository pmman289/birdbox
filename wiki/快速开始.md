# 快速开始

本页给出从全新部署到第一条 Established 会话的最短路径。生产环境仍应完整阅读 [[部署与初始化]] 和 [[生产最佳实践]]。

## 1. 启动 Birdbox

```bash
git clone https://github.com/pmman289/birdbox.git
cd birdbox
cp .env.example .env
```

生成两个不同的数据库密码：

```bash
openssl rand -base64 36
openssl rand -base64 36
```

编辑 `.env`：

```dotenv
BIRDBOX_IMAGE_TAG=latest
MYSQL_DATABASE=birdbox
MYSQL_USER=birdbox
MYSQL_PASSWORD=替换为第一个随机密码
MYSQL_ROOT_PASSWORD=替换为第二个随机密码
BIRDBOX_BIND_ADDRESS=127.0.0.1
BIRDBOX_PORT=3000
BIRDBOX_SECURE_COOKIE=false
BIRDBOX_SHUTDOWN_TIMEOUT_MS=1800000
```

启动并检查：

```bash
docker compose config
docker compose pull
docker compose up -d
docker compose ps
curl -fsS http://127.0.0.1:3000/api/health
```

健康接口应返回 `"status":"ok"`。使用 HTTPS 反向代理时，把 `BIRDBOX_SECURE_COOKIE` 改为 `true` 后重建 Birdbox 容器。

## 2. 设置管理员密码

打开 `http://127.0.0.1:3000`。首次访问直接设置 `admin` 密码，不需要初始化令牌。

密码长度必须为 10 到 128 个字符。初始化完成后，初始化接口永久关闭，页面以后显示登录表单。

## 3. 准备第一个 BIRD 节点

先确认目标节点：

- BIRD 2 已运行；
- 主配置文件存在，例如 `/etc/bird/bird.conf`；
- 控制 Socket 存在，例如 `/run/bird/bird.ctl`；
- Socket 所属组不是 `root`，并可授权给专用用户；
- Birdbox 容器可以访问目标 SSH 地址和端口。

在 Birdbox 中进入“资源管理” > “受管节点” > “添加节点”，填写：

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| 节点名称 | `MoeDove-HK` | 仅用于显示 |
| 节点地址 | `router.example.net` | IP 或主机名，不含用户名 |
| SSH 用户 | `birdbox` | 专用非 root 用户；不存在时脚本自动创建 |
| SSH 端口 | `22` | 目标 sshd 端口 |
| Router ID | `192.0.2.1` | Birdbox 节点信息，不覆盖 Include 模式主配置中的 Router ID |
| 默认会话端口 | `179` | 新会话的本地 BGP 端口默认值 |
| 主配置 | `/etc/bird/bird.conf` | 系统正在使用的主配置 |
| 生成配置 | `/var/lib/birdbox/generated.conf` | Birdbox 独占的 Include 文件 |
| 控制 Socket | `/run/bird/bird.ctl` | `birdc -s` 使用的 Socket |

点击“生成准备脚本”，在目标节点以 root 执行完整脚本。脚本会创建用户、安装受限公钥、准备版本目录、追加 Include、运行 `configure check` 和 `configure`。

回到页面点击“测试连接”。只有测试通过后才能保存新节点。

## 4. 添加 eBGP Peer

进入“资源管理” > “eBGP 远端” > “添加 Peer”：

- 选择所属节点；
- 填写易识别的名称；
- 填写邻居 IP；
- 填写远端 ASN；
- BGP 端口通常保持 `179`。

Peer 只是远端定义，添加它不会生成 BGP 会话，也不会变更节点配置。

## 5. 创建 BGP 会话

回到“会话与拓扑”：

1. 选择节点和 Peer。
2. 检查自动生成的协议名称；同一节点内必须唯一。
3. 本地地址默认留空，让 BIRD 自动选择。
4. 填写本地 ASN；它不能与远端 ASN 相同。
5. 本地端口通常保持 `179`。
6. 至少启用 IPv4 或 IPv6 Channel。
7. 首次测试建议导入选择“导入所有”，导出选择“不导出”。
8. Direct Peer 保持 `Direct`；跨跳 Peer 才选择 `Multihop` 并设置 TTL。
9. 点击“预检配置”。
10. 确认生成配置后点击“应用会话变更”。

应用时页面顶部会显示等待提示。Birdbox 会预检完整节点配置、部署 Include，并最多等待约 25 秒观察会话是否 Established。返回“正在等待远端 Peer”不表示部署失败，只表示在观察窗口内尚未建立。

## 6. 验证结果

检查以下位置：

- 顶部全局状态没有显示“控制器异常”；
- 拓扑中的 Peer 状态为正常；
- “节点会话”表中协议为 Established；
- “节点配置”中可以看到生成的 BGP Protocol；
- “变更日志”记录了添加或应用等关键变更。

如果未 Established，先检查远端 ASN、地址、Address Family、端口、防火墙和对端配置，再阅读 [[故障排查]]。

## 推荐的首次导出策略

不要在第一条会话上直接选择“导出所有”。推荐先创建一个 IPv4 或 IPv6 CIDR Define，只放入明确允许发布的前缀，然后把导出策略设为“导出指定 CIDR Define”。

```text
192.0.2.0/24
198.51.100.0/24
```

完成后重新预检和应用会话。这样即使节点路由表中存在意外路由，也不会被自动发布。
