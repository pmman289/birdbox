# 部署与初始化

推荐使用仓库提供的 Docker Compose 部署 Birdbox 和 MySQL 8.4。Compose 同时提供只读根文件系统、非 root 用户、健康检查、日志轮转和持久化卷。

## 前置条件

- Docker Engine 24 或更新版本；
- Docker Compose v2；
- 宿主机可以拉取 Docker Hub 镜像；
- 宿主机或容器网络可以访问所有受管节点的 SSH 端口；
- 生产环境已有 HTTPS 反向代理或受限管理网络；
- 可以同时备份 MySQL 和 Birdbox 数据卷。

## Docker Compose 部署

```bash
git clone https://github.com/pmman289/birdbox.git
cd birdbox
cp .env.example .env
```

编辑 `.env`：

```dotenv
BIRDBOX_IMAGE_TAG=latest
MYSQL_DATABASE=birdbox
MYSQL_USER=birdbox
MYSQL_PASSWORD=替换为随机应用密码
MYSQL_ROOT_PASSWORD=替换为另一个随机 root 密码
BIRDBOX_BIND_ADDRESS=127.0.0.1
BIRDBOX_PORT=3000
BIRDBOX_SECURE_COOKIE=false
BIRDBOX_SHUTDOWN_TIMEOUT_MS=1800000
```

不要把 `.env` 提交到 Git。两个 MySQL 密码必须不同，也不应复用管理员登录密码。

启动：

```bash
docker compose config
docker compose pull
docker compose up -d
docker compose ps
curl -fsS http://127.0.0.1:3000/api/health
```

`docker compose config` 必须在启动前成功，避免变量缺失或 Compose 语法错误。MySQL 变为 `healthy` 后 Birdbox 才会启动。

## 镜像版本选择

`BIRDBOX_IMAGE_TAG=latest` 适合首次安装和测试。生产环境验证完成后，建议固定具体版本 tag 或镜像 digest：

```dotenv
BIRDBOX_IMAGE_TAG=0.01a
```

或者：

```dotenv
BIRDBOX_IMAGE_TAG=0.01a@sha256:替换为实际digest
```

固定版本使升级、审计和回滚可重复。升级前先在测试环境验证目标镜像。

## 监听地址

默认只允许本机访问：

```dotenv
BIRDBOX_BIND_ADDRESS=127.0.0.1
```

需要局域网访问时可以改为：

```dotenv
BIRDBOX_BIND_ADDRESS=0.0.0.0
```

然后重建容器：

```bash
docker compose up -d --force-recreate birdbox
```

监听 `0.0.0.0` 只表示接受所有网卡的连接，不代表访问已经安全。必须通过防火墙只允许管理网段访问 `BIRDBOX_PORT`，未初始化实例不得暴露到公网。

## HTTPS 反向代理

生产环境推荐保持 Birdbox 绑定 `127.0.0.1`，由同机 Nginx 提供 HTTPS。示例：

```nginx
server {
    listen 443 ssl http2;
    server_name birdbox.example.net;

    ssl_certificate     /etc/letsencrypt/live/birdbox.example.net/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/birdbox.example.net/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $http_host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 1900s;
        proxy_send_timeout 1900s;
    }
}
```

启用 HTTPS 后设置：

```dotenv
BIRDBOX_SECURE_COOKIE=true
```

并重建 Birdbox：

```bash
docker compose up -d --force-recreate birdbox
```

如果在纯 HTTP 上错误地启用 Secure Cookie，浏览器不会发送登录 Cookie，会表现为登录后仍回到登录页。反向代理必须保留原始 `Host`，否则同源检查可能拒绝写操作。

## 首次初始化

首次打开页面时直接设置固定账户 `admin` 的密码，不存在初始化令牌。

- 密码长度为 10 到 128 个字符；
- 设置完成后初始化接口关闭；
- 首次设置成功会自动创建登录会话；
- 登录 Cookie 为 `HttpOnly`、`SameSite=Strict`，有效期 12 小时；
- 登录失败有速率限制。

建议使用密码管理器生成至少 20 个字符的随机密码。初始化完成后立即确认 HTTPS、备份和管理网访问控制。

## 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `BIRDBOX_IMAGE_TAG` | `latest` | Docker 镜像 tag 或 digest |
| `MYSQL_DATABASE` | `birdbox` | MySQL 数据库名 |
| `MYSQL_USER` | `birdbox` | MySQL 应用用户 |
| `MYSQL_PASSWORD` | 必填 | MySQL 应用密码 |
| `MYSQL_ROOT_PASSWORD` | 必填 | MySQL root 密码 |
| `BIRDBOX_BIND_ADDRESS` | `127.0.0.1` | 宿主机发布地址 |
| `BIRDBOX_PORT` | `3000` | 宿主机 HTTP 端口 |
| `BIRDBOX_SECURE_COOKIE` | `false` | HTTPS 环境设为 `true` |
| `BIRDBOX_SHUTDOWN_TIMEOUT_MS` | `1800000` | 最长 30 分钟等待正在执行的远端部署结束 |

Compose 内部固定让 Birdbox 监听容器的 `0.0.0.0:3000`。外部可访问范围由 `BIRDBOX_BIND_ADDRESS` 控制。

## 部署验证

```bash
docker compose ps
docker compose logs --tail=100 birdbox
docker compose logs --tail=100 db
curl -fsS http://127.0.0.1:3000/api/health
```

健康接口返回 `deploymentLocked:true` 时，表示另一个配置部署正在执行，不代表进程异常。不要在部署期间重启容器。

## 数据位置

- `birdbox_mysql`：库存、认证状态、部署恢复日志；
- `birdbox_data`：控制器 SSH 私钥、SSH 公钥、`known_hosts` 和迁移数据。

两个卷必须作为同一恢复点一起备份。只恢复数据库而缺少原控制器 SSH 身份时，Birdbox 会拒绝静默生成新身份，以免绕过节点主机身份绑定。

## 停止与删除

正常停止：

```bash
docker compose stop
```

保留数据地删除容器：

```bash
docker compose down
```

不要执行 `docker compose down -v`，除非明确要永久删除数据库、认证状态、SSH 私钥和 `known_hosts`。
