# 节点接入与退役

Birdbox 通过专用非 root SSH 用户管理节点，只维护一个独立的 BIRD Include 文件。首次接入需要管理员在目标节点执行一次 root 准备脚本。

## 接入前检查

在目标节点确认：

```bash
bird --version
test -f /etc/bird/bird.conf
test -S /run/bird/bird.ctl
stat -c '%U:%G %a %n' /run/bird/bird.ctl
birdc -s /run/bird/bird.ctl show status
```

要求：

- BIRD 2 已安装并运行；
- 主配置和 Socket 路径与页面填写一致；
- Socket 用户组不是 `root`；
- 目标系统有 `birdc`、`stat`、`install`、`mktemp`、`awk` 和 `grep`；
- Birdbox 容器到目标 SSH 地址的网络可达；
- 准备脚本执行者有 root 权限。

如果 Socket 属于 `root:root`，应先按发行版的 BIRD 服务配置创建专用控制组并让 Socket 使用该组。Birdbox 不允许把专用 SSH 用户加入 root 组。

## 添加节点

进入“资源管理” > “受管节点” > “添加节点”。

### 字段说明

| 字段 | 说明 |
| --- | --- |
| 节点名称 | 页面显示名称，1 到 80 个字符 |
| 节点地址 | SSH IP 或主机名；用户名必须单独填写 |
| SSH 用户 | 小写 Linux 用户名，必须是非 root 用户 |
| SSH 端口 | 1 到 65535 |
| Router ID | 有效 IPv4；Include 模式下作为节点资产信息，不写入系统主配置 |
| 默认会话端口 | 节点展示的默认 BGP 端口；当前新会话表单默认使用 179 |
| 主配置 | 系统实际加载的主配置文件 |
| 生成配置 | Birdbox 独占的 Include 路径 |
| 控制 Socket | 当前 BIRD 实例的控制 Socket |

不同 Birdbox 节点不能使用相同的 `SSH 主机 + SSH 端口 + 生成配置路径`，防止两个库存对象同时控制同一部署目标。

## 准备脚本做什么

点击“生成准备脚本”，在目标节点以 root 执行。脚本会自动：

1. 验证主配置、Socket 和必需命令。
2. 读取 Socket 的非 root 用户组。
3. 创建缺失的专用系统用户和 Home 目录。
4. 把专用用户加入 BIRD Socket 用户组。
5. 创建生成配置目录和 `versions` 目录。
6. 创建初始空配置并让生成配置路径指向它。
7. 安装带 `restrict` 的 Birdbox 控制器 SSH 公钥。
8. 在主配置末尾添加精确的 Include 行。
9. 执行 `birdc configure check` 和 `birdc configure`。
10. 失败时恢复主配置备份。

脚本可重复执行。它不会重复创建用户、公钥或 Include，也不会接管属主不符合预期的既有目录或普通文件。

## 对已有主配置的影响

Include 模式生成文件开头只有说明注释，不会生成全局 `router id`，也不会生成 Birdbox 自己的 Device Protocol。因此目标主配置中已有的以下内容不会被覆盖：

```bird
router id 192.0.2.1;

protocol device kernel_device {
}
```

准备脚本只在找不到同路径的有效 Include 时追加：

```bird
include "/var/lib/birdbox/generated.conf";
```

仍需注意全局标识符冲突。Birdbox 生成的 Define、Function、Filter、RPKI Table、Static Protocol 和 BGP Protocol 名称不能与主配置或其它 Include 中的声明重名。节点测试和每次预检会让目标 BIRD 检查完整主配置，因此冲突会在写入库存前被阻止。

## 测试连接

脚本成功后点击“测试连接”。测试会检查：

- SSH 是否可连接；
- 专用用户是否能读取和切换受管配置；
- Include 路径和目录权限是否正确；
- 控制 Socket 是否可访问；
- 目标是否运行受支持的 BIRD 2；
- 当前完整候选配置是否可以通过预检。

新节点必须测试通过后才能保存。

## SSH 主机身份与 known_hosts

Birdbox 使用托管 Ed25519 控制器密钥和独立的 `known_hosts` 文件。首次连接采用 TOFU：自动接受新主机密钥并写入 `known_hosts`。后续如果主机密钥变化，SSH 会拒绝连接。

主机重装或合法轮换 SSH Host Key 时，先在可信通道核对目标指纹：

```bash
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

备份 Birdbox 数据卷后，检查现有记录。默认端口使用主机名，非默认端口使用 `[host]:port`：

```bash
docker compose exec birdbox \
  ssh-keygen -F 'router.example.net' -f /var/lib/birdbox/ssh/known_hosts

docker compose exec birdbox \
  ssh-keygen -F '[router.example.net]:2222' -f /var/lib/birdbox/ssh/known_hosts
```

确认新指纹可信后才删除旧记录：

```bash
docker compose exec birdbox \
  ssh-keygen -R 'router.example.net' -f /var/lib/birdbox/ssh/known_hosts
```

然后重新执行“测试连接”，让 Birdbox 接受并保存新密钥。不要为了绕过错误直接删除整个 `known_hosts` 文件；已有受管节点而文件缺失或为空时，Birdbox 会拒绝启动。

## 编辑节点

节点保存后，SSH 目标、SSH 用户、端口、部署模式、主配置路径、生成配置路径和 Socket 路径不可直接修改。这些字段决定远端所有权边界，修改时必须退役节点后重新接入。

可编辑的显示名称、Router ID 和默认会话端口会对节点执行候选配置检查和同步。Include 模式下修改节点 Router ID 不会改写主配置中的 Router ID；如需修改系统 Router ID，应在目标节点维护主配置并先做 BIRD 预检。

## 安全退役

正常退役前必须删除：

- 该节点的所有 BGP 会话；
- 该节点的所有 Peer；
- 仅属于该节点的 Define、Function、Filter、RPKI，并从多节点资源的指定范围中移除该节点；
- 该节点的所有 Static 资源。

点击“安全退役”后，Birdbox 会：

1. 生成空的 Birdbox Include；
2. 在目标节点预检；
3. 部署空配置；
4. 从库存删除节点。

安全退役不会自动删除主配置中的 Include 行、生成配置目录或 `authorized_keys` 中的控制器公钥。确认节点不再纳管后手工清理。

## 强制遗忘

节点永久离线且无法安全退役时，可展开“节点永久离线”并选择“强制遗忘”。页面要求输入：

```text
遗忘 <node.id>
```

强制遗忘会级联删除节点、Peer、会话和仅属于该节点的资源；多节点 Define、Function、Filter、RPKI 会保留并从作用域中移除该节点。该操作不连接目标节点，也不清理远端配置。之后必须按顺序人工处理：

1. 从主配置移除 Birdbox Include 并执行 `configure check`、`configure`；
2. 删除远端生成配置和版本目录；
3. 从专用用户 `authorized_keys` 删除控制器公钥；
4. 重新纳管或复用主机前检查 BIRD 当前配置。

全局资源不会因强制遗忘一个节点而删除，因为它们可能仍服务其它节点。
