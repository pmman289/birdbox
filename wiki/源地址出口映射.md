# 源地址出口映射

“源地址出口映射”按源 IPv4 CIDR 选择远端出口。它适合业务源地址需要经不同上游或不同 WireGuard/OSPF 出口转发的场景。

Birdbox 自动管理 BIRD 配置；Linux 的 `ip rule` 和 OpenWrt 路由规则由管理员按界面提供的计划手工执行。

## 创建映射集

进入“资源管理” > “源地址出口” > “新增映射集”。

1. 选择下发节点。选择“所有节点”会影响以后新增的节点；节点条件不一致时，建议使用“指定节点”。
2. 填写映射集名称。
3. 添加一个或多个出口组。每个出口组填写一个出口地址，再添加对应源 CIDR。Linux 路由表默认自动分配；如果节点已有 table，可在“Linux 路由表”中填写未占用的 table ID。
4. 大量地址可使用“批量导入 JSON 映射”。格式是“出口地址 -> 源 CIDR 数组”。
5. 需要访问内部网络时，开启“复制内部路由”并选择 IPv4 CIDR Define。
6. 点击“预检、保存并下发 BIRD”。

示例：

```json
{
  "172.20.177.36": [
    "162.141.136.139/32",
    "162.141.136.138/32"
  ],
  "172.20.177.38": [
    "82.47.33.189/32"
  ]
}
```

## BIRD 与系统规则

每个出口组都会创建独立 BIRD 表、recursive static default 和 Kernel Protocol。出口地址由 `master4` 递归解析，因此 OSPF 或其它 IGP 路径变化时，策略表会随 BIRD 收敛更新。

保存成功只表示 BIRD 已下发。随后在“手工操作计划”中完成系统规则：

- Linux：复制 root 脚本并执行。脚本可重复执行；需要持久化时，直接执行界面生成的 systemd 安装/更新脚本。它会安装 helper、unit 并立即启用服务。
- OpenWrt：按 LuCI IPv4 Rules 清单填写 Priority、Source 和 Lookup table。更新或停用时，先删除界面列出的旧规则，再添加当前规则。界面不自动写入 OpenWrt 路由规则。

可使用 `ip -4 rule show`、`ip -4 route show table <table>` 和 `ip -4 route get <destination> from <source>` 验证。

## 限制与排障

- 仅支持精确 IPv4 CIDR，不接受 `10.0.0.0/8+` 之类的 BIRD 扩展前缀语法。
- 同一节点上，源 CIDR 不能在两个启用映射集中重叠。
- 出口地址必须能在 `master4` 中解析；BIRD 表里没有默认路由时，应先检查 IGP/静态到出口地址的路由。
- 删除或停用映射集后，仍需执行清理计划。没有清理的 `ip rule` 可能让流量走到空策略表。
- 如果 `ip route get` 报源地址不可用，先确认测试源地址确实配置在本机接口或用于转发流量。
- Linux 路由表可手工指定 1–2147483647，但不能使用 0、253、254、255，也不能与节点已有路由策略表冲突。
