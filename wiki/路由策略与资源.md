# 路由策略与资源

Birdbox 提供 Define、Function 和 Filter 三类策略资源。它们会作为完整 BIRD 声明写入节点 Include，并可被会话策略、Static 或其它资源引用。

## 资源作用域

创建资源时可选择：

- “所有节点”：全局资源，部署到每个受管节点；
- 指定节点：只部署到该节点。

节点级资源可以引用全局 Define 或同一节点的 Define。全局资源不能引用节点级 Define，因为它必须在所有节点上成立。

修改全局资源会预检并部署所有受影响节点，操作耗时通常高于节点级资源。生产环境优先使用最小必要作用域。

## BIRD 名称

Define、Function、Filter、RPKI、Static 和 BGP Protocol 共享节点的 BIRD 全局标识符空间。名称必须：

- 以字母或下划线开头；
- 后续只包含字母、数字和下划线；
- 最长 64 个字符；
- 在同一节点生成配置中唯一；
- 避开 Birdbox 内部协议名称。

界面会根据显示名称自动生成 BIRD 名称，但保存前仍应检查。

## Define

Define 支持三种类型。

### IPv4 CIDR 列表

```text
192.0.2.0/24
198.51.100.0/24
10.0.0.0/8+
```

### IPv6 CIDR 列表

```text
2001:db8::/32
2001:db8:100::/48
2001:db8::/32{48,64}
```

单个 CIDR Define 最多 256 个不重复条目。支持 BIRD 的 `+`、`-` 和 `{low,high}` 前缀模式。

注意：这些扩展模式可以用于 Filter 匹配，但 Static 只接受精确 CIDR，例如 `2001:db8::/32`。Static 编辑器会自动过滤扩展模式。

### 表达式

```bird
65000
```

或：

```bird
(65000, 100)
```

表达式必须是一条 Define 值，不能包含额外顶层分号语句。可以引用声明顺序更早、作用域兼容且已启用的 Define。

## Define 顺序

资源表中的上移、下移按钮控制声明顺序。引用另一个 Define 的表达式必须排在依赖项之后。

编辑器的“可用 Defines”只显示当前作用域可用且在当前 Define 之前声明的资源。调整顺序会重新预检并部署受影响节点。

## Function

Function 必须包含一条完整声明：

```bird
function customer_route()
{
  if net ~ CUSTOMER_PREFIXES then {
    bgp_local_pref = 200;
  }
}
```

无参数 Function 可在会话可视化策略中作为步骤调用。有参数 Function 仍会部署，并可从其它 BIRD 源码引用，但资源表会显示“仅源码引用”，不会出现在会话 Function 选择器中。

Function 支持上移和下移。被其它 Function 引用的声明必须出现在使用者之前。

## Filter

Filter 必须包含一条完整声明：

```bird
filter customer_export
{
  if net ~ CUSTOMER_PREFIXES then accept;
  reject;
}
```

Filter 用于接管某个 Channel 的完整 Import 或 Export 决策。使用自定义 Filter 时，应确保所有路径最终都有明确的 `accept` 或 `reject`。

## 源码编辑器

编辑 Function、Filter 和表达式 Define 时：

- `Tab` 缩进，`Shift+Tab` 减少缩进；
- `Enter` 保留当前缩进；
- 右侧显示光标行列；
- 可搜索当前作用域可用的 Define 和 Function，并点击快速插入；
- 单个源码上限为 32 KiB；
- 一个 Function 或 Filter 资源只能有一条顶层声明。

Birdbox 会做结构检查，但最终语义以目标节点原生 BIRD 预检为准。

## 启用和停用

停用资源后，它不会写入节点配置。已启用的资源不能引用已停用的 Define，会话也不能使用已停用的 Function、Filter 或 CIDR Define。

如果资源仍被引用，停用、改名、改变作用域或删除通常会被阻止。先更新所有引用者，再修改被引用资源。

## 引用保护

资源表显示引用计数。Birdbox 会阻止以下危险操作：

- 删除被会话引用的 Define、Function 或 Filter；
- 删除被 Static 引用的 Define；
- 改名仍被其它源码引用的 Define；
- 删除或改名仍被策略引用的 RPKI 名称或 ROA Table；
- 把资源移动到引用者不可见的作用域；
- 让已启用资源引用已停用依赖。

源码引用通过 BIRD 标识符识别。即使引用只存在于自定义源码中，也应先按依赖顺序修改使用者。

## 保存和部署

“预检、保存并应用”不是草稿保存。它会对资源影响的所有节点执行：

1. 构造候选库存；
2. 生成完整节点配置；
3. 目标原生 BIRD 预检；
4. 部署节点；
5. 提交库存。

失败时不会保留半成品资源。全局资源可能触发多节点部署，应预留足够维护窗口。

## 推荐依赖顺序

```text
基础 CIDR Define
  -> 表达式 Define
  -> 通用 Function
  -> 业务 Function
  -> Filter
  -> BGP 会话
```

先创建底层资源，再创建引用者；删除时反向执行。命名中加入用途和地址族，例如 `prefix4_customer_export`、`function_set_customer_pref`、`filter_transit_import`。
