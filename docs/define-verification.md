# Define 管理改进与验收

本轮完善 Define 的编辑、引用维护、服务端预检及 IRR 快照一致性。保留现有 IPv4/IPv6 前缀模式、表达式、节点作用域、手工声明顺序、自动同步和事务部署机制。

## 操作流程

1. 在资源管理的 Defines 中添加或编辑。标题持续显示当前 BIRD 名称、未保存状态和影响节点数。
2. 编辑前缀或表达式。手工前缀支持文本导入、去重整理、统计和导出；上限仍为 256 条。IRR 快照只读、可搜索，最多展示 200 条，导出包含完整快照。
3. 点击“预检并查看变更”。服务端规范化候选，返回前缀增删、直接和间接引用、节点配置及差异；不同节点的预检错误分别保留。动态资源的差异包含独立资源片段。
4. 确认差异后点击“确认应用”，再明确确认下发。应用仍进行完整服务端预检，并沿用部署锁、CAS、journal 和回滚。
5. 修改草稿会立即使预检失效。取消、Esc、切换资源和离开页面均保护未保存内容。库存冲突时保留草稿，可加载最新配置对比，并选择采用远端或明确保留本地后重新预检。

引用统计和编辑器采用共享扫描器，覆盖 Define/Function/Filter 源码、BGP、Static、OSPF、源地址出口、Kernel、Pipe，并沿策略依赖追踪间接引用。注释及字符串不计数；同名但作用域不同的资源分别处理。可编辑的资源可从引用列表跳转。

IRR 来源不变时，修改备注、节点范围或启停复用服务端快照，不依赖 IRR 查询成功。来源变化才重新展开。通过预检的快照绑定到候选，应用不会再次展开。客户端不能覆盖服务端同步状态。“立即同步并应用”仅针对已保存来源获取新快照，有未保存修改时禁用；先展示预检和增删，之后明确确认才应用。测试展开结果单独标识，不作为配置修改，也不隐式替换已保存快照。同步期间来源、地址族、节点范围或启用状态变化会拒绝旧结果，保留现行配置。调整刷新间隔会重新安排刷新时间。

## 接口

- `GET /api/defines/editor-context?id=...`：返回库存 revision、资源和引用；新建时省略 id。
- 资源在编辑期间被删除时，editor-context 返回最新 revision 与 `resource: null`。对比页明确显示已删除，可保留本地草稿作为新资源；不会自动重建或下发。
- `POST /api/defines/preview`：接受候选及可选编辑 id、inventoryRevision，返回规范化资源、previewId、candidateHash、变更及逐节点结果；不写库存、不应用。
- 原 POST/PUT Define 接口接受 `mode: "apply"`、previewId、candidateHash、inventoryRevision。预检有效期为 5 分钟，绑定完整配置和库存版本，过期或修改后必须重试。
- DELETE 和手动同步接受可选 inventoryRevision。旧 API 客户端仍执行完整事务预检。
- 配置、旧配置和差异中的凭据统一脱敏。

## 边界

本轮不改变自动同步的应用策略，不增加前缀变化比例阈值或历史版本回退，不自动重排声明顺序；已有空结果、数量上限、预检失败及部署回滚保护继续生效。

## 当前复核（2026-10-19）

修复共享策略编辑器中无指令的 HTML `<template>`：该容器内的引用、冲突对比和预检结果被浏览器作为惰性内容处理，造成预检成功却看不到变更。改为普通显示容器，Function/Filter 同样受益。

引用保护按受管节点隔离。同名 Define 可以分属不同节点；改名、删除时，只检查作用域重叠的源码引用。真实 HTTP 测试覆盖两节点同名定义、只在第二节点存在的 Function 消费者、第一节点预检/改名/删除，以及第二节点仍受到保护。Static 自定义路由块也按作用域检查，不会因其它节点同名符号被错误阻止操作。

固定操作栏在版本冲突时显示“版本冲突 · 查看处理方式”，其它失败显示“操作未完成 · 查看错误详情”。点击后滚动并聚焦错误区域，能够继续读取最新版本、对比或重试，不会丢失草稿。

保留草稿时，以服务端最新资源更新“已保存”基线。即使用户没有修改打开时的配置，保留已被远端修改的旧内容也会正确标为未保存，关闭仍需确认；应用成功后重新打开恢复为已保存。移动端覆盖旧的通用隐藏规则，固定操作栏持续显示预检、应用状态文字。

浏览器验证包含逐节点预检失败、成功节点结果保留、应用失败回滚后的草稿与完整重试、直接/间接引用及阻止误删。真实 HTTP 流程覆盖创建→只读预检→确认应用→重开编辑→停用→重新启用→删除；没有拦截 Define 或 Dashboard API，远端使用隔离模拟 Agent。

## 草稿切换与响应丢失补充（2026-10-19）

IPv4、IPv6、表达式及手工/IRR 来源分别保留编辑内容。切到另一地址族或来源时，不会把原先前缀或表达式当作新类型继续提交；切回即可恢复原输入。编辑器显示保留规则，空 IRR 来源显示“尚未生成快照”，搜索无结果与没有快照分别提示。

前后端共用不丢弃输入的前缀拆分逻辑，保留 `{24,28}` 内部逗号。去重按服务端的空白规范化规则识别重复，不再意外去掉多余括号并把非法输入变成另一条合法前缀。非法模式和地址族冲突在服务端返回 400，库存和远端配置不变。

创建或更新的应用响应丢失时，保留本地草稿并阻止直接重试。读取候选 ID 对应的已保存资源进行比较；确认保留草稿后，如果创建实际已经成功，后续使用同一 ID 更新，避免重复创建。用户也可直接采用已保存配置。

修复表达式末尾 `#` 注释吞掉生成分号的问题。原生解析样例增加带注释常量，并在主机及无网络隔离容器的 BIRD 2.17.5 / 2.19.0 检查通过。
