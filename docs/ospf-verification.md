# OSPF 工作区与事务验收（2026-10-19）

## 完整候选与草稿

预检和应用使用同一份服务端规范化候选，包含 IRR 等独立 Include 文件。预检返回逐节点结果、生成配置和有界差异；节点失败不隐藏其它结果。候选绑定库存 revision、域和有效期，CAS 检查在部署锁和事务重试内执行。布局存储独立于路由库存、部署锁和预检令牌。

保存草稿只写独立草稿记录；重新打开恢复草稿，首次应用走创建接口。草稿中的新认证密钥在脱敏重载后由服务端恢复，经过审阅的候选密钥绑定到应用。空域可以应用以清理原成员配置，草稿域可以直接删除。

页面等待节点库存与域一起加载后再启用操作，避免节点迟到使刚完成的预检失效。普通 Dashboard/节点刷新不重置本地编辑基线。切换域、离开页面和删除操作保护未保存内容。CAS 或未知结果保留草稿，可读取最新版本对比，再明确采用远端或保留本地。

## 结果与运行态

失败响应附带事务 ID、逐节点成功/失败/回滚/未知/未尝试结果及回滚摘要。回滚失败保留 journal，页面显示未知，成功完成后不能重复应用同一候选。预检失败仍可打开成功及失败节点配置。应用成功后的列表刷新失败不会误报下发失败。

运行态按域、节点和版本隔离。通过 `bird.protocol` 查询实际协议状态，不从邻居数量推断协议是否运行。已有只读 RPC 增加可选 `ospfState: true`，同时查询 `show ospf <协议名>` 的实际 Area 类型、接口、邻居和完全邻接数量；SSH/local 使用等价查询。Area 查询失败独立返回，不隐藏成功的协议或另一个版本。旧 Agent 忽略标志时提示升级；缺失统计显示未知，有效零值保持为零。草稿 Area 明确收在“配置参考”中，不冒充节点实际状态。

实际 Area 摘要来自节点返回的 Area ID 并集。新建域立即清除原域运行态并取消旧请求，避免轮询前短暂显示上一个域的状态。解析器验证协议名和 Area 总数，拒绝混入其它协议或把不完整输出当作完整统计。
